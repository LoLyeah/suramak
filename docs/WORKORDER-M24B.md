# WORKORDER — M24B: citation-verified notes (Minutes, Action items, EN↔ID brief)

Roadmap: `docs/reports/M21-roadmap.md` #7. Otter-class output, done honestly:
the notes are generated by the user's OWN endpoint, and **every timestamp in
them is checked against real segments** — a citation that names audio which
does not exist is removed and counted, never shipped as if it were true.

## The user job

A 40-minute meeting. One tap gives Minutes with `[12:31]` citations that
actually jump into the recording, an Action items list with owners as spoken,
and — for mixed EN/ID meetings — a bilingual brief. Everything stays local
except the single request to the endpoint the user configured.

## Deliverables

1. **Three presets**, one shared mechanism: `Minutes`, `Action items`,
   `Bilingual brief (EN↔ID)`. Each is a system prompt + an output contract:
   Markdown, citations as `[mm:ss]` or `[hh:mm:ss]`, no invented speakers,
   no invented times, keep the source language (the brief may add a summary
   line in the other language).
2. **Generation** reuses the existing polish client and its endpoint/model
   settings — no new HTTP path, no new crate. Input: the transcript's segments
   (index, start_ms, speaker label if any, text), chunked if long. One request
   per preset (chunk-then-merge only if the segments exceed the existing
   chunk budget; state which path ran).
3. **The validator** (`check_notes`): every bracketed time token is parsed and
   matched to a segment start within ±1_500 ms. Valid tokens are rewritten to
   the canonical segment time. Invalid tokens are **removed from the text** and
   counted; the result carries `citations_removed: u32` and
   `citations_checked: u32`. A token pointing past the end, a malformed token,
   and a duplicate of the same segment are each counted separately in a
   breakdown.
4. **Storage** (additive schema, v12): `notes(transcript_id, preset, body_md,
   citations_checked, citations_removed, model, created_at)`, one row per
   (transcript, preset) — regenerating replaces it. Reading is ordered by
   preset.
5. **UI**: an editor action `Notes` opens a sheet listing the three presets
   (with "not configured" state when no endpoint is set), a Run button, and
   the stored result view: the Markdown body rendered, plus one honest line —
   `12 citations checked · 1 removed (no matching audio)` — and
   `Export .md` / `Copy`. Phone and desktop share this state machine; the
   sheet uses the existing Sheet plane.
6. **Failure paths, named**: no endpoint configured; endpoint error (status +
   message); model returned no citations at all (allowed — say "no citations
   returned" rather than pretending); a transcript under 20 s (allowed, notes
   are just short).

## Verification

- Validator tests: exact match; match within 1.4 s; 2 s off (removed);
  `hh:mm:ss` form; several tokens per line; malformed `[banana]` untouched
  (not a time token); a token past the end; a duplicate; the removed count and
  breakdown; valid tokens rewritten to segment times.
- Store tests: v11→v12 upgrade on a populated library; one row per
  (transcript, preset); regenerate replaces; ordering.
- UI tests: the sheet's three presets, the not-configured state, the result
  line's copy with 0 removed and with N removed, and Export writing the exact
  stored markdown.
- A mock-endpoint test for each preset: prompt carries the segments, the
  response is stored, and a response with fabricated timestamps lands with
  them stripped.
- fmt/clippy -D warnings; NDK check + clippy on both Android crates; one full
  workspace run (baseline 1371).
- Report: `docs/reports/M24b-citation-notes.md` with real before/after output
  from the mock endpoint (verbatim, including a stripped citation).

## Do NOT

- No new crates; no cloud service of our own; no automatic on-transcribe
  generation (user-triggered only); no changes to the polish request shape
  beyond the new preset prompts; no editor/typography restyle; no CI edits;
  no git commit/push; no sudo.
