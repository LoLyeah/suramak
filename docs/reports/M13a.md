Results: `Finished release profile … in 5m 17s` (arm64) and `Finished dev profile … in 2m 03s` (x86_64). Both were *full* first builds — whisper.cpp, bundled libopus (`opusic-sys` 0.7.5 via `cc`/cmake), rusqlite's bundled SQLite, ring, and the whole Rust dep tree compiled for the target.

**The one fix that stood in the way: the CMake toolchain shim** (`scripts/android/ndk-toolchain.cmake`, new).

`whisper-rs-sys` builds whisper.cpp through the `cmake` crate, which forwards only a toolchain file. The NDK's `android.toolchain.cmake` reads `ANDROID_ABI`/`ANDROID_PLATFORM` from *CMake variables* and — with them unset — silently defaults to `armeabi-v7a`. `cargo-ndk` v4.1.2 exports `ANDROID_ABI`/`ANDROID_PLATFORM` in the environment (correct per target), but neither cmake-rs nor whisper-rs-sys forwards them into CMake. The shim maps the environment values into CMake and then includes the NDK's own toolchain file; `build.sh` exports it as `CMAKE_TOOLCHAIN_FILE` (whisper-rs-sys passes any `CMAKE_*` env var through as a cmake define, so this lands exactly where cmake-rs looks for it). It was validated standalone first with a throwaway CMake project (configure + compile + `file`/`readelf`: `ELF 64-bit LSB shared object, ARM aarch64 … for Android 29, built by NDK r27d`), then by the real builds. Nothing else was needed: no cfg gating fixes, no changes to `CC_*`/`AR_*` handling (cargo-ndk sets those correctly), no target-specific dependency changes, no behavioral changes anywhere.

### 2.4 `scripts/android/build.sh` (new)

One wrapper, installs nothing. It: discovers the NDK (`$ANDROID_NDK_HOME` → `$ANDROID_NDK_ROOT` → `~/android-ndk/android-ndk-r27d` → standard SDK locations) and **refuses a non-pinned revision**; checks `cargo-ndk` and both rustup targets with actionable errors; exports `ANDROID_NDK_HOME`/`ANDROID_NDK_ROOT` and `CMAKE_TOOLCHAIN_FILE` (the shim); builds `arm64-v8a` release and `x86_64` debug through cargo-ndk with `--platform 29`; prints each produced `.so` with its size and `file` type; exits non-zero if an expected artifact is missing. Usage: `scripts/android/build.sh [abi …]` (default both; a single ABI while iterating), `SURAMAK_ANDROID_PLATFORM` override.

## 4. Deviations and notes (with whys)

1. **The CMake shim is the one build-blocking fix** (§2.2) — needed because cmake-rs forwards only a toolchain file and the NDK toolchain silently defaults to `armeabi-v7a` without `ANDROID_ABI`. Everything else built as-is.
2. **`c++_static` vs `c++_shared`**: the NDK's toolchain defaults `ANDROID_STL` to `c++_static` (the plan's preference), so whisper.cpp's objects carry the static libc++; but `whisper-rs-sys` unconditionally emits `cargo:rustc-link-lib=dylib=c++_shared` for Android, so the final `.so` records a `libc++_shared.so` DT_NEEDED. Making that consistent (patch the emit or ship `libc++_shared.so`) is packaging work for M13b+; it does not affect this compile/link gate. Recorded in `docs/android.md` so it is not re-derived later.
3. **libopus is built but not pulled into the `.so`**: `libopus.a` is produced per ABI by `opusic-sys` (cmake + NDK clang), and the link directive is present; the archive members only enter the `.so` once something references them — nothing in the M13a smoke path decodes audio, so the linker keeps them out. That is the normal lazy static-link behaviour; the decode path (and with it libopus) enters the `.so` the moment M13b's shell references `decode`. The build gate for libopus is its per-target C build.
4. **x86_64 is debug, arm64 is release** — as the workorder allows ("debug acceptable for x86_64 if time forces — say which"). arm64 (the shipping ABI) is the release gate.
5. **`build.sh` runs two cargo-ndk invocations, not one `-t arm64-v8a -t x86_64` command** — profiles differ per ABI (release gate vs debug emulator ABI) and cargo takes one profile per invocation. Both ABIs are still built by one script run, and the literal single-invocation command from the workorder was run separately as well (§3.3, exit 0). The smoke fn was strengthened mid-task (adding the `system_info()` reference) so the final link *must* resolve whisper/ggml — the `.so` grew from 1.2 MB to 1.9 MB (arm64) and 564 whisper/ggml symbols now appear in it.
6. **One test flake observed (pre-existing class, documented)**: the first `cargo test --workspace` (run concurrently with a cross-build) failed in `suramak-asr`'s `system_info_names_the_linked_whisper_build` with a truncated system-info string (` = 1 | F16C = 1 | …`) — the classic in-process whisper concurrency race that `ci.yml` already documents (`RUST_TEST_THREADS: "1"`). It is not reproducible: the same test binary passed plain, the full workspace passed plain afterwards, and the full suite passes under the repo's CI-parity `RUST_TEST_THREADS=1` (43 s, 468 passed). No code in `suramak-asr` or its tests was touched by M13a.
7. **The android seam module's unit tests are Android-only** (behind `cfg(target_os = "android")`, as the workorder requires), so they compile only for Android targets — proven with `cargo ndk … test --no-run` (exit 0). They cannot execute on this VPS (no emulator/device); executing them is M13b's emulator job.
