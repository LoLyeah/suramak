## The `speech` crate — pinned against the real API

- `speech = "0.8"` resolves to **0.8.7** (the latest 0.8.x; 0.9.0 exists but the workorder pins 0.8.x). Its published requirement pulls `doom-fish-utils 0.3.3` (pure Rust).
- The crate's build.rs runs `swift build` over its `swift-bridge/` package and links Speech/AVFoundation/Foundation/CoreMedia — **macOS + Swift toolchain only**. The dependency lives under the macOS target and behind the feature, so Linux resolves it into `Cargo.lock` and never builds it.
- The exact API surface the module uses was pinned from docs.rs **and the crate's sources** (0.8.7, vendored in the cargo cache):
  `analyzer::{SpeechTranscriber (new/is_available/supported_locales/supported_locale_equivalent_to/transcribe_in_path), SpeechTranscriberPreset::TimeIndexedTranscriptionWithAlternatives, SpeechTranscriptionResult{text: SpeechAttributedText{text, spans: Vec<SpeechAttributeSpan{start, end, audio_time_range: Option<SpeechTimeRangeAttribute>}>}, audio_time_range, is_final}}`,
  `asset_inventory::{AssetInventory (status_for_modules / asset_installation_request_for_modules), AssetInventoryStatus, AssetInstallationRequest::download_and_install}`,
  `recognizer::SpeechRecognizer::{authorization_status, request_authorization}` + `error::AuthorizationStatus` (non-exhaustive → wildcard arm), and the bridge fact that `spxRunSpeechAnalyzer` calls `spxEnsureAuthorized()` (source-verified).

## Routing (pure function — `suramak-asr::engine::resolve_engine`)

- `fast == false` (the default) → **exactly today's routing** for every language.
- `fast == true` **and** `setting == Auto` **and** a forced language, in order:
  1. macOS + a SpeechTranscriber-covered language + `speech_transcriber_ready()` (feature compiled, OS probe + locale positive) → **SpeechTranscriber**;
  2. else a Parakeet-covered language + `parakeet_ready()` → **Parakeet**;
  3. else **Whisper**, with a warning naming the blocker(s) that apply (`SpeechTranscriber is macOS-only` / `…not available on this macOS version or for this locale` / `this build was compiled without the … feature` / `the Parakeet model is not installed (…)`).
- **Indonesian (`id`, `ID`, `id-ID`) → never either fast engine** — hard guards in `models::{parakeet_covers, speech_transcriber_covers}` plus the invariant asserted over the whole availability matrix.
- **Non-macOS → SpeechTranscriber is never selected** (even a hypothetical availability claiming otherwise).
- Auto-detect (`None`) → Whisper; uncovered languages → Whisper; an explicit `coreml`/`metal`/`cpu` → that whisper backend (the toggle never overrides an explicit request).

## Deviations from the WORKORDER (with reasons)

1. **The macOS module was type-checked against the real crate on Linux** (the
   workorder assumed a blind write). The `speech` crate's build.rs skips the
   Swift bridge under `DOCS_RS=1`, so the verbatim module body + the
   crate-calling probes were checked for the host **and** `aarch64-apple-darwin`
   targets (Design §5). No behavior change; strictly stronger evidence. The
   probe is throwaway (`build/probe-speech/`, gitignored — same pattern as
   M10A's `build/probe-darwin`).
2. **Authorization handling + `NSSpeechRecognitionUsageDescription`** (not named
   in the workorder). Source-verified: the crate's Swift bridge gates the
   analyzer path on `SFSpeechRecognizer.authorizationStatus() == .authorized`
   (`spxEnsureAuthorized`), so without a request the engine could never run on
   the owner's Mac, and without the plist key the prompt itself would fail.
   The engine therefore requests authorization once (the documented Apple flow)
   and a denial degrades to Whisper with the fix spelled out. Added to
   `packaging/Info.plist`; noted in §29.
3. **`EngineAvailability::current` gained a `language` parameter.** The
   SpeechTranscriber availability probe is language-dependent (the OS must
   support the locale), and the workorder requires availability to be a
   pure-function input. Call sites updated (the whisper Core ML fallback passes
   `None` — it only needs the platform).
4. **The settings *label* copy was updated along with the caption.** The
   checkbox said “Parakeet for covered languages”, which is wrong once the
   macOS order starts with SpeechTranscriber; now “fast engines for covered
   languages”. Same row, same control, copy only (the workorder's “caption
   update only”).
5. **The degradation warning text names both blockers** for a covered language
   when neither fast engine can run (`SpeechTranscriber is macOS-only; the
   Parakeet model is not installed … — using cpu`). Intended per the workorder
   (“extend the message to name the blocker”); the **engine chosen is unchanged
   in every case** — feature-off builds route identically (asserted).
6. **The Linux CI job also gained a stub check+test step.** The workorder
   specified the macOS job; adding the Linux step enforces the refusal-stub gate
   in CI at negligible cost. The macOS job gained only the one bounded feature
   build; the smoke step is untouched.
7. **`speech = "0.8"` resolves to 0.8.7 + `doom-fish-utils 0.3.3`** (0.8.7's
   published requirement is `>=0.1, <0.4`; 0.9.0 exists but the workorder pins
   0.8.x). `Cargo.lock` additions only.
8. **The analyzer runs are not cancellable mid-call.** The crate exposes no
   progress/cancel hooks on the file path; the pipeline checks the cancel token
   at the stage boundaries around the engine call and reports two honest
   milestones (50/100). Documented in the module, pipeline and ENGINES.md.
9. **The module resolves `en` → `en-US`-style locales via the OS check first,
   then a small region-hint table** — the OS remains authoritative
   (`supportedLocale(equivalentTo:)`); the hints only help it resolve a bare
   code. Owner-verify territory.

## Boundaries (honest)

- **Every SpeechTranscriber runtime behavior is owner-verify.** The module
  cannot execute on Linux (the Swift bridge cannot build there), and the darwin
  cross-checks cannot build the C dependencies (pre-existing `ring` class). The
  macOS CI feature build (Design §7) + the owner's Mac are the real validation;
  the Linux evidence is the stub + routing + mapping + a real-crate type-check.
- **No speed or quality numbers are claimed.** The measured Core ML-whisper vs
  SpeechTranscriber comparison is USER_SMOKE §29 and gates the later
  auto-default flip. No WER claims, no ANE claims.
- The **first run** on a Mac may sit in the one-time authorization prompt and
  the OS asset download (tens of MB, once) — noted in §29; there is no progress
  reporting for those (the crate offers none).
- **No `models` entries / pins** for this engine by design (OS-managed assets,
  auto-updated by macOS); `doctor` reports the state instead.
- `live` transcription stays whisper; the fast engines run on file jobs only.
- The `speech` crate's Rust API is type-checked, but its Swift bridge and the
  framework linkage are validated only on a Mac (CI + owner).
- The exact runtime shape of `SpeechTranscriber` results (span granularity,
  whether one file yields one final result or several) is **not** observable
  from Linux; the mapping is three-tiered and conservative precisely because of
  that (documented on `segments_from_results`).
