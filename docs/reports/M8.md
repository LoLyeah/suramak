## What was implemented

### 1. `suramak-playback` — the new crate

| file | contents |
|---|---|
| `src/source.rs` | `resolve_playback_source(&Transcript) -> PlaybackSource` + `transcript_duration_ms` + the two user-facing hints (keep-audio / missing file). Pure; **no DB field involved** (see Deviations 2). |
| `src/segments.rs` | `segment_index_at(&[Segment], position_ms)` (binary search over segment starts) and `format_mmss(u32)`. Pure. |
| `src/transport.rs` | `Command` (`Play { from_ms }` / `Pause` / `Resume` / `Seek { ms }` / `Stop`), `PlaybackState`, `Playback` — the state machine the editor draws from. **Egui-free and device-free.** |
| `src/engine.rs` | the cpal half: `Engine` (UI-thread handle), `EngineError`, `Status`, `RateRange`/`pick_output_rate`, `mono_mixdown`, `resample_mono`, the engine thread + the lock-free audio callback. |
| `tests/engine.rs` | device-tolerant engine tests: a missing file fails cleanly, a real file either plays or reports a clean device state — never a panic. |

**Engine architecture** (`src/engine.rs`), the workorder's protocol:

- One `suramak-playback` thread owns the decoded audio **and** the `cpal::Stream` (`cpal::Stream` is `!Send`, so it is created and dropped on that thread). The UI thread only sends `Command`s over an `mpsc` channel.
- `Play` is the first thing that touches the output device: the thread decodes the file with `suramak_core::decode::decode_file`, mixdowns to mono, resamples with rubato (`FftFixedIn`, the same resampler core's whisper path uses) when the device does not advertise the file's rate, opens the stream and starts the playhead. A headless machine therefore reaches a clean, pollable error state instead of "the app failed to start".
- Position: `Arc<AtomicU32>` milliseconds, written by the callback and read by `Engine::poll()`. Seeks are handed to the callback through a second atomic (`pending_seek`, `SEEK_NONE` sentinel) — the callback is allocation-free and lock-free; the callback owns its sample cursor.
- Failure paths are values, never panics: `EngineError { message, retryable }` — `retryable` for device errors (a device that goes away may come back), clear for source errors (a file that cannot be read). Device errors during playback land in a set-once slot the thread drains and republishes.
- Rate/format policy: `pick_output_rate(ranges, file_rate, default_rate)` → the file's rate when the device advertises it (no resampling), else the device's default rate; mono is preferred, else the device's channel count (the callback duplicates mono into every channel); F32/I16/U16 sample formats are supported (same three as the capture path).

**Source resolution** (`src/source.rs`) — the matrix the tests pin:

| transcript | file state | result |
|---|---|---|
| imported file (`Source::File`) | `audio_path` exists | `Ready { path }` |
| imported file | path set but gone | `Unavailable { "the source audio is gone — import the file again to play" }` |
| imported file | no path at all | `Unavailable { "no audio was saved for this transcript — import the file to play" }` |
| recording, `keep_audio` on | path exists | `Ready { path }` |
| recording, `keep_audio` **off** | temp file deleted after the save | `Unavailable { "keep audio was off — the recording's file is gone (turn on “Keep recordings” in Settings)" }` |

**Transport rules** (`src/transport.rs`), all unit-tested:

- `Idle → Playing` = `Play { from_ms: position }` (a playhead parked at the end restarts from 0);
- `Playing → Paused` = `Pause`; `Paused → Playing` = `Resume` (the engine keeps its cursor);
- `seek` clamps to the duration; while a session is live it emits `Seek`, while idle it only remembers the position (the next `Play` starts there), while the source is unavailable it is a no-op;
- `stop` always resets the position to 0, returns to the source's initial state and emits `Stop` only when a session was live (that is what keeps the M2/M3 effect-count tests green);
- a polled position is only taken while `Playing`/`Paused` — a stale poll after `stop` must not resurrect the playhead; `finished` parks the playhead at the duration and returns to `Idle`;
- a **retryable** unavailable state (device error) keeps the control armed: pressing play retries; a missing source is not retryable and emits nothing.

### 2. Runtime + app wiring (`crates/suramak-ui`)

- `Effect::Playback { source: Option<PathBuf>, command }` — a `Play` carries the file to open; the runtime keys one engine session by path (`PlaybackSession { path, engine }`), replaces it when the transcript changes and **releases it on `Stop`** (leaving the editor must not park a decoded buffer).
- `Runtime::playback_status() -> Option<Status>` is the polled channel (the `capture_rms()` pattern): position, duration, finished, terminal-once error; a thread-spawn failure is reported through the same shape. `main.rs::pump()` polls it every frame and feeds `AppState::on_playback_status`.
- `AppState` owns the transport (`pub playback: Playback`): `open_editor` rebuilds it from `resolve_playback_source` + `transcript_duration_ms`; `toggle_playback`/`seek_playback`/`on_playback_status` are the three touch points; `busy()` includes `playback.is_playing()` so frames keep coming while the playhead moves.
- **Stopping rules** (all state-tested): leaving the editor (`back_home`), switching transcripts (`select_library`), importing (`begin_import`), deleting the open transcript, and starting a recording (`start_recording`) stop playback and reset the position; a `Stop` is emitted only when a session was live, so the pre-M8 effect-count assertions still hold.

### 3. Editor UI (`app/editor.rs`)

- The strip is now the **playback strip**: play/pause control (painted triangle / two bars — no emoji-font dependency, dimmed when nothing can play), the M1 waveform + ticks, the playhead line in `palette.accent` (same time mapping as the ticks — one `axis_x`/`strip_ms_at` pair for ticks, playhead and clicks), click-to-seek anywhere on it, and the `mm:ss / mm:ss` readout on the right.
- Unavailable audio replaces the playhead with the reason, in words (the keep-audio hint / the missing-file hint / the engine's device message).
- Segment rows: the **active** row (containing the playhead, `segment_index_at`) gets an accent-tinted background; the list calls `scroll_to_rect` for it **only while playing** — a paused playhead never yanks the scroll. Clicking a row's timestamp seeks to that segment's start (keeping playback if it was playing); the `TextEdit` still owns plain clicks inside the text.

## Deviations from the WORKORDER (with reasons)

1. **Acceptance 5 cannot pass from Linux — documented, not worked around.** `cargo check -p suramak-playback --target aarch64-apple-darwin` fails **before any M8 code compiles**, in two transitive C dependencies that need the Apple SDK:
   - `ring v0.17.14` (via `suramak-core → reqwest → rustls → ring`): its build script needs an Apple C toolchain; with `CC_aarch64_apple_darwin=clang` it gets as far as `fatal error: 'bits/libc-header-start.h' file not found` — there is no macOS SDK. The same failure hits `cargo check -p suramak-core --target aarch64-apple-darwin` (pre-existing; the M4 report already lists it as blocker 4).
   - `cpal → coreaudio-rs → coreaudio-sys 0.2.18`: the workorder's premise ("cpal's coreaudio backend is pure Rust + frameworks") does **not** hold for cpal 0.15.3 — coreaudio-sys runs bindgen against `AudioUnit/AudioUnit.h` and fails with `fatal error: 'AudioUnit/AudioUnit.h' file not found`.
   Neither can be fixed from this VPS (no osxcross, no SDK, `sudo` forbidden), and the repo's own CI already encodes exactly this policy for `suramak-asr`: *“`cargo check --target aarch64-apple-darwin` is only meaningful for pure-Rust crates … need an Apple C toolchain (no osxcross on this runner)”* (`.github/workflows/ci.yml`). Evidence + the substitute checks are in the acceptance section and Deviations 9 below.
2. **No DB field / migration needed** (the workorder's preferred branch). `transcript.audio_path` already carries the source path for imports **and** recordings — the pipeline stores `Some(input)` for both (`suramak-asr/src/pipeline.rs`), and `keep_audio` off deletes the temp file *after* the save, so a recording whose file is gone is exactly `Source::Recording` + a stale/absent path. Tested for both source kinds.
3. **`Stop` releases the engine session** (and the next `Play` re-decodes). Not specified by the workorder; it keeps a decoded buffer (hundreds of MB for long audio) from being parked while the user is away from the editor. Pause/resume/seek keep the session.
4. **Click-to-seek, not drag-scrub**: the strip reacts to `clicked()` only, per “click anywhere on the strip to seek”. A drag does not scrub.
5. **Duration is the transcript's estimate until the engine knows better**: the strip uses the last segment's end so it is meaningful before the first play; the engine's real duration replaces it on the first poll.
6. **A retryable device error keeps the control armed.** The strip shows the reason (like the missing-audio case) but the play control stays enabled so the user can retry after plugging a device in; only a missing source dims it. Without this, “no output device” would be a dead end for the rest of the session.
7. **Gaps have no active segment**: the highlight is “the segment containing the playhead” (`start ≤ pos < end`), so it goes dark between segments and after the last one. The auto-scroll simply keeps the last target; nothing jumps.
8. **README**: the one bullet asked for, plus a one-line addition to the `Layout` crate list (`crates/suramak-playback`) so the list stays truthful.
9. **The Linux UI build now pulls cpal/ALSA** (M4's `cargo tree -p suramak-ui | grep cpal == 0` invariant changes by design — playback is a shipping feature, the workorder says Linux is fine with `libasound2-dev`). The `capture` feature stays OFF: `cargo tree -p suramak-ui --target x86_64-unknown-linux-gnu -e features` shows only `suramak-asr feature "default"`.
10. **The engine integration tests are device-tolerant** (either the playhead advances or the engine reports a clean *retryable* device error), so they are green on this VPS/CI and on a machine with audio.

## Blockers (honest status)

1. **No audio was actually heard.** This VPS has no output device, so the engine's playback path (stream open → callback → advancing playhead) has never run end to end here — it is exercised only up to the clean device error, plus unit tests of the pure pieces (`pick_output_rate`, mixdown, resampling, the ms↔cursor mapping). Real playback on macOS is `docs/USER_SMOKE.md` item 14.
2. **Acceptance 5 does not pass from Linux** and the workorder's premise about cpal was inaccurate (coreaudio-sys + bindgen + SDK headers); the exact evidence is above. An osxcross toolchain would be needed to change that.
3. **The pause glyph (two bars) is not visually verified** — reaching a `Playing` state needs a device; the glyph is driven by the state tests only.
4. **Device-rate edge cases are untested on real hardware**: a device that only advertises multi-channel formats, a non-default sample format, or a rate change mid-session (unplugging headphones) are code paths that only run with a device. The device-lost path republishes a retryable error instead of dying (log-verified only through the missing-device case here).
