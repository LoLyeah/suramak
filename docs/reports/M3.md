## What was implemented

### 1. `suramak-asr::capture` — microphone + system audio, `capture` still OFF by default

- **Pure helpers** (compiled and unit-tested on *every* build — no cpal, no device): `mono_mixdown`, `resample_16k` (core's rubato path), `RollingRms` (O(1) sliding 100 ms window), `write_recording_wav` (16 kHz mono i16), and the **source-resolution function** `resolve_input_source(source, devices, system_audio_available)` with `ResolvedSource`/`SourceResolution`.
- **cpal session** behind `capture`: `list_input_devices` / `list_input_devices_detailed` (name + default marker), `start_recording` (default device) / `start_recording_with(&AudioSource)`, `Recorder` (device name, sample rate, live rolling RMS, `warning()`, `stop() -> AudioBuffer`).
- New feature **`capture-test`** (implies `capture`): device-enumeration test that opens **no stream** and asserts a list (possibly empty) — compiles everywhere, run on the macOS CI job.
- `CAPTURE_COMPILED` compile-time probe so dependents can gate UI unconditionally.
- `capture` still OFF in default builds: `cargo tree -p suramak-ui --target x86_64-unknown-linux-gnu` matches **0** for `cpal|rfd|zbus|ashpd`; Linux builds need no audio runtime.

### 2. Record flow in `suramak-ui` (M1 visuals kept)

- The M1 chrome-strip red dot is now live on capture builds (`views.rs`): M1 glyph and palette; dimmed when unavailable. Disabled while a job runs; on Linux default builds it is dim + a static home caption + a click note — all honest text, no fake affordance.
- **Record route** (`app/record.rs`): auto title `Recording <date>`, elapsed clock (`mm:ss.t`), **live RMS meter** (accent bar) and the **rolling waveform painter** (96 centred bars in the M1 wave greys), Stop button (idempotent while the runtime finalises), plus the source-resolution warning line (Addendum A's "visible warning" when a configured device is missing).
- **State machine** in `app/mod.rs` (pure, tested): `RecordState { Idle, Recording, Failed }`; `start_recording` → `Effect::StartCapture`; meter samples via `record_sample` (rolling window); `tick` drives the elapsed clock; `stop_recording` → `Effect::StopCapture { title }`; failure/leave paths. A live recording **owns the audio session** (imports/library clicks ignored until Stop).
- **Stop → wav → existing pipeline**: the runtime stops the session (stream first, then any tap), resamples to 16 kHz, writes the wav, then `on_recording_stopped` feeds the file through the *existing* `begin_import` → worker → progress → editor path. No new pipeline.
- **`keep_audio` handling** (documented choice): `true` → `<data>/recordings/<stem>.wav` (kept); `false` → `<system temp>/suramak-recordings/<stem>.wav`, **deleted after the transcript is saved** (not at `Finished`) — a failed library write keeps the audio for a retry. File stem = title with `:` → `-` (filesystem-safe; the pipeline titles the transcript from the file name, so the library shows `Recording 2026-10-13 14-05-33`).
- **Recording format (user storage decision)**: 16 kHz mono **16-bit signed PCM** WAV, both kept and temp — the samples whisper consumes, re-transcribable with zero conversion:

  | Format | Size per hour |
  |---|---|
  | **16 kHz mono i16 (chosen)** | **115.2 MB/h** |
  | 16 kHz mono f32 | 230.4 MB/h |
  | 44.1 kHz mono f32 (device rate) | 635.0 MB/h |
  | 48 kHz mono f32 | 691.2 MB/h |
  | 48 kHz stereo f32 (typical mic) | 1 382.4 MB/h |

  Quantization error ≤ 1/32767 (≈ −90 dBFS), far below any microphone noise floor. The shared `decode::write_wav` (f32) is unchanged; the recording path uses the additive `decode::write_wav_i16`.

### 6. `crates/suramak-taps` (new, Addendum A) — macOS system audio via CoreAudio process taps

- Pure Rust (objc2 message sends + `extern "C"` declarations + `core-foundation`; **no new C build deps**), mac code behind `cfg`, no-op stubs elsewhere → **`cargo check -p suramak-taps --target aarch64-apple-darwin` passes from Linux** (verified, see acceptance).
- API: `SystemTap::start(&TapConfig)` creates a `CATapDescription` (stereo global tap, **all processes except Suramak** via `initStereoGlobalTapButExcludeProcesses:`, unmuted, private) + a **private aggregate device**, returns `device_uid()` (CoreAudio UID), `device_name()`, `device_id()` (lazy `kAudioHardwarePropertyTranslateUIDToDevice`), and `stop()`/`Drop` tearing down **aggregate first, then tap**, idempotently.
- **One parameter, not a reshape**: `TapConfig { processes: ProcessSelection }` — `ProcessSelection::AllExcept(Vec<u32>)` today; a per-app milestone adds `Only(Vec<u32>)` as a sibling variant.
- Exact API calls + availability are documented in `src/macos.rs` (`CATapDescription` & `AudioHardwareCreate/DestroyProcessTap` 14.2+; aggregate-device + `AudioObjectGetPropertyData` 10.9+/10.0+; `kAudioTapPropertyUID` 14.2+). The two 14.2+ functions are resolved with `dlsym(RTLD_DEFAULT, …)` **at call time** (Rust cannot weak-import) and the `CATapDescription` class check is the availability gate → `TapError::OsTooOld` on older macOS, so the binary stays loadable there.
- **No ScreenCaptureKit** anywhere (documented fallback only).

## Deviations from the WORKORDER (with reasons)

1. **`capture` re-enabled for macOS/Windows only** (M3 §2 as written): the target-gated `suramak-asr { features = ["capture"] }` dep is back — `cargo tree -p suramak-ui --target aarch64-apple-darwin` shows `cpal v0.15.3` again; Linux stays capture-free.
2. **The stub `Recorder` carries the real method surface** (`device_name`/`sample_rate`/`rms`/`warning`/`stop`) so the UI/runtime type-check on all platforms; it can never be constructed (`start_recording*` always error).
3. **Core/asr additions are strictly additive** (all documented in-code): core `paths::recordings_dir`, `download::download_with_progress` (`download` now delegates with a no-op callback), `decode::write_wav_i16`, `Settings.recording`/`RecordingSettings`/`AudioSource` (`#[serde(default)]` → old files load); asr `capture::CAPTURE_COMPILED`, `InputDeviceInfo`, `list_input_devices_detailed`, `start_recording_with`, `resolve_input_source`, `ResolvedSource`, `SourceResolution`, the pure helpers, `Recorder::warning()`, feature `capture-test`. Nothing existing changed shape or behavior.
4. **The core download API had no progress callback** (the workorder says to read it): `download_with_progress` was added (additive) and the model manager polls a byte counter written by a detached download thread; progress also covers resumed downloads (first callback = pre-existing `.part` size).
5. **Addendum A, cpal adaptation**: cpal 0.15.3's coreaudio backend exposes **no UID/AudioDeviceID lookup** (verified against its source: `Device { audio_device_id, is_default }` is opaque, only `name()` is public). `suramak-taps` returns the UID as specified; capture opens the aggregate device by matching its **unique name** ("Suramak System Audio"), and the UID stays the authoritative handle (teardown, diagnostics, `kAudioHardwarePropertyTranslateUIDToDevice` resolution). A cpal that exposes UID lookup makes it a one-line change.
6. **Recording file stem vs title**: the visible title is `Recording <date>`; the file stem replaces `:` with `-` (macOS/Windows-legal), and the transcript title comes from the file name via the existing pipeline.
7. **Temp-recording lifecycle** (documented choice, §2 above): deleted after the transcript is *saved*, not at `Finished`.
8. **Recording format**: 16 kHz mono i16 PCM per the user's storage decision (size table above); the shared f32 `write_wav` keeps its existing callers.
9. **`AppState.capture_available`** is a field seeded from `capture::CAPTURE_COMPILED` — the record state machine (start/stop/timer/failure) is thus headless-testable on Linux, where the real probe is false.
10. **Model delete is direct** (no confirmation dialog), matching the CLI's `models remove`; the row's Delete is only enabled when something is installed/partial.
11. **Home now renders the cross-view status line** — the record-dot note needs a visible place on the route where the dot is clicked.
12. **macOS/Windows UI builds cannot be compiled from Linux** (pre-existing C-dep limitation, M1/M1.5/M2): the capture/tap *glue* inside `suramak-asr`/`suramak-ui` compiles on the macOS CI runner; `suramak-taps` alone is darwin-checked here.

## Blockers (honest status)

1. **No microphone and no system audio in this environment, and none can be emulated.** What is *exercised*: every pure helper, the record state machine, source resolution (all branches + the Linux `SystemAudio` error path), the Linux unsupported path in the real app, device-enumeration compilation/tests, and the recording wav round-trip. What is **not** exercised anywhere in this environment: opening a real input device, the live RMS/waveform against real audio, the tap creation + TCC prompt + aggregate-device open, and record→transcribe end-to-end with real audio. Those are the **macOS CI runner** (build + enumeration) and the **user smoke on the Mac** (actual recording).
2. **`suramak-taps` runtime behavior is unverified** — the crate compiles for `aarch64-apple-darwin` from Linux, but no tap has ever been created anywhere in this environment. The exact calls and their availability annotations are documented in `src/macos.rs`; the first real execution is the user smoke. If the 14.2+ selectors/keys differ in practice, the fix is localized to that one file.
3. **macOS/Windows UI builds (incl. the capture/tap glue) cannot be compiled from Linux** — pre-existing C-dependency limitation (rustls/ring, whisper-rs-sys); the macOS CI job builds the real bundle and now runs the enumeration test.
4. `cargo test --workspace` keeps the 3 ignored whisper e2e tests (they need the model; CI runs them with `--ignored`).
