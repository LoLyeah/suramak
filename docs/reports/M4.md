## What was implemented

### 1. LLM polish usable in-app (WORKORDER §1)

**`crates/suramak-ui/src/app/polish.rs` — the egui-free state machine** (new module, all rules unit-tested):

| Piece | Summary |
|---|---|
| `polish_config(settings, key_present)` | The gate: a non-empty `settings.polish.base_url` **and** a key (injected bool; the runtime passes `keychain::get_api_key().is_ok()` — OS keychain on macOS/Windows, `SURAMAK_OPENAI_API_KEY` on Linux, per M3). Empty model → `gpt-4o-mini` (same default as the CLI). Errors carry the actionable "where to configure it" text. |
| `PolishState` | `Idle → Running(PolishRun{originals}) → Review(PolishReview{rows}) / Failed{message}`; `is_running()`/`is_reviewing()`; part of `AppState` (`polish`, `polish_undo`, `polish_configured`), so `busy()` keeps the tick alive while a run polls. |
| `AppState::start_polish()` | Gate (configured + not running/reviewing + editor with ≥1 segment) → snapshots the editor **including unsaved edits** → `Effect::PolishTranscript`; stores the sent `(idx, text)` pairs for the review and the undo. |
| `on_polish_done(result)` | A validated reply opens the review (belt-and-braces alignment re-check: count + per-segment idx); any failure → `Failed{raw error}`, transcript untouched. Stray results are ignored. |
| `accept_polish()` | Batch: writes the tidied text into the editor buffers, persists **immediately** via `Effect::SaveEdits` (not the debounce), arms the one-step `PolishUndo{previous, segments}`; if nothing changed it is a no-op with a status line. |
| `undo_polish()` | One step: restores the previous buffer texts and persists them the same way; the marker is consumed. |
| `discard_polish()` | Closes a review (or dismisses a failure) without touching the transcript; a run in flight cannot be discarded (batch only, no cancel). |
| `opening another transcript` | `open_editor` clears the polish state + undo marker — a review applies by segment index and must never leak onto a different transcript (state-tested). |

**Failure rule (defined + tested)**: when the reply does not validate — it drops or merges segments, swaps ids, sends empty text, is not JSON, or the endpoint errors — the **whole run fails**, the transcript is left exactly as it was and the raw backend/reply error is shown. No partial apply. Core's `parse_and_validate` already rejects the reply; the UI re-checks alignment and turns any `Err` into the failed state. Covered pure (count-mismatch message, misaligned ids, HTTP 500 through the mock) and end-to-end (a mock that merges 2 segments into 1 → `Bad polish response: segment count mismatch: expected 2, got 1` → originals kept, store untouched).

**Runtime (`runtime.rs`) — background thread, existing patterns**: `Effect::PolishTranscript` → `Runtime::start_polish` resolves the config, spawns a detached **`suramak-polish`** thread (core's client is blocking HTTP; never the ASR worker, never the UI thread) with a shared `Arc<Mutex<Option<Result<…>>>>` slot; the thread stores the outcome and calls `egui::Context::request_repaint()` (exactly like the bridge does for worker events). `Runtime::polish_status()` is polled in `main.rs`'s `pump()` (same shape as the M3 download poll, terminal-once) and feeds `AppState::on_polish_done`. `polish_configured` is seeded at startup and refreshed after a settings save (the base URL/key can change there).

**Review UI (`app/editor.rs`, additive to the M1 composition)**:
- a **polish bar** under the title: `Polish` (enabled only when configured + editor open; otherwise the disabled button + the note explaining Settings/`SURAMAK_OPENAI_API_KEY`), `Accept`/`Discard` while reviewing, `Undo` after an accept, `Polish`+`Dismiss` on failure with the raw error in red;
- while a run is in flight or a review is open the transcript rows are replaced by the **polish panel**: "polishing N segment(s)…" or the **side-by-side `original | tidied` review** per segment (timestamp + two wrapping columns), batch only.

## Deviations from the WORKORDER (with reasons)

1. **No core/asr changes at all.** The workorder permitted strictly-additive ones; none were required (core's `OpenAiCompat`/`PolishBackend`/`parse_and_validate`/keychain API already sufficed). Verified with an empty `git diff` for those crates.
2. **Two small app bugs found and fixed while verifying the E2E (files already in scope):**
   a. **tracing was dead in the app since M1**: the default filter `suramak_ui=info` matches no target (the binary target is `suramak`), so `EnvFilter` dropped every event. Changed to `suramak=info`; the app now logs the wgpu adapter, surface config, and the polish lifecycle (`polish: starting the background run` / `reply validated` / `run failed`).
   b. **polish transport errors hid their cause**: reqwest's `Display` for a send failure is only "error sending request for url (…)". The runtime now walks the source chain (`error_chain`), so the UI shows e.g. `… — caused by: client error (Connect) — caused by: tcp connect error — caused by: Connection refused (os error 111)`. This is exactly what diagnosed the harness issue in the E2E below.
3. **The review is modal for the editor** (documented rule): while a run is in flight or a review is open, the transcript rows are replaced by the polish panel — a polished text can never land on a buffer that changed underneath it; opening another transcript drops a pending review and the undo marker (state-tested).
4. **Accept persists immediately** (`Effect::SaveEdits`) instead of waiting for the 1 s autosave debounce (the workorder says "persist via the store" on Accept); the undo persists the same way. An accept whose tidied texts equal the stored text is a no-op (no save, no undo marker) with a status line.
5. **Batch-only, no cancel**: a run in flight cannot be discarded; failures can be retried (`Polish`) or dismissed.
6. **Mica/Acrylic mode mapping** was not fixed by the workorder (only the DW values were); the policy lives in `WindowsBackdrop::for_mode` (Auto → Mica, Always → Acrylic) so it is unit-tested on Linux. `Never` returns before any DWM call.
7. **`windows.rs` also extends the frame** (`DwmExtendFrameIntoClientArea`, −1 margins) and the crate gains the `Win32_UI_Controls` feature (`MARGINS` lives there) — the workorder's "minimal transparency/titlebar flags winit needs". Immersive dark mode and the frame extension are best-effort (documented in-code); the backdrop call's failure is `BackdropFailed`, matching the M1 stub's error contract.
8. **`scripts/mac-smoke.sh` adds one step** (model bootstrap `models download tiny`, a no-op when installed) — the CLI e2e cannot pass on a fresh machine otherwise. The rest of the sequence is exactly the workorder's.
9. **The CLI test sets process-global env** (`XDG_DATA_HOME` + `SURAMAK_OPENAI_API_KEY`) and restores it; it is the only test in the CLI test binary, and the mock tests in the UI binary serialize on a shared mutex. The env-var key path is the production path on Linux (macOS/Windows use the keychain, never touched by these tests).
10. **The in-app UI tests go through the real `Runtime`**, not just the state machine — the strongest reading of "the UI polish flow must be testable headless against a mock endpoint". The pure tests cover the gate/lifecycle rules without network.
