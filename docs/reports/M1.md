## What was implemented

### `crates/suramak-glass` — native window material, cross-checkable from Linux

| File | Summary |
|---|---|
| `src/lib.rs` | `GlassMode {Auto, Always, Never}`, `GlassConfig`, `GlassError` (manual `Display`/`Error`, no new deps), `apply(&Window, GlassConfig) -> Result<(), GlassError>` with cfg dispatch (macOS → `macos`, Windows → `windows`, else → `stub`) |
| `src/macos.rs` | PLAN §1 steps 1–6 exactly: rwh 0.6 AppKit handle → retain content `NSView` → `NSView::window()` → `NSWindow`; `setOpaque(false)` + `NSColor::clearColor()`; `setTitlebarAppearsTransparent(true)` + style mask `\| FullSizeContentView` + `setTitleVisibility(Hidden)` (native traffic lights stay); runtime `AnyClass::get(c"NSGlassEffectView")` → typed `NSGlassEffectView` wrapper (style `Regular`, sized to `contentView().bounds()`) else `NSVisualEffectView` (`BehindWindow` / `UnderWindowBackground` / `Active`); content-view swap so the material sits **behind** winit's view, both views `ViewWidthSizable \| ViewHeightSizable` (risk-2 mitigation). Window appearance pinned to `DarkAqua` (see deviations 4) |
| `src/windows.rs` | DWM stub: HWND from the rwh 0.6 `Win32WindowHandle`, `DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE, &DWMSBT_TRANSIENTWINDOW, 4)`; compile-checked only (never exercised) |
| `src/stub.rs` | Linux/other no-op returning `Ok(())` — the UI paints its own opaque dark window there |

### `crates/suramak-ui` — winit 0.30 + manual egui-winit/egui-wgpu shell (bin `suramak`)

| File | Summary |
|---|---|
| `src/main.rs` | `ApplicationHandler` loop; smoke mode (`SURAMAK_SMOKE_SECS=N` → N seconds of live app after window creation → write `build/smoke_ok.txt` only when ≥1 frame was presented → exit 0; otherwise exit 1 with the reason, never a fake file); `WaitUntil`-driven deadline; `CloseRequested` exits |
| `src/shell.rs` | Window (1280×800, min 900×600, `with_transparent(true)`); wgpu init with an **explicit backend chain** (Linux Vulkan → GL; macOS Metal; Windows DX12 → Vulkan; `SURAMAK_WGPU_BACKENDS` override; each entry tried normal + `force_fallback_adapter`, every failure reason printed); surface config with sRGB format, `Fifo`, and `PostMultiplied` → `PreMultiplied` → … alpha-mode pick (PLAN §1 step 7); clear color `{0,0,0,0}` every frame (step 8); `egui_winit::State` + `egui_wgpu::Renderer` manual wiring (no eframe); viewport-command pump → `window.drag_window()`; `#[cfg(target_os="macos")] suramak_glass::apply(...)`; smoke report (frames, adapter, backend, alpha mode, size, ppp) |

## Deviations from PLAN / WORKORDER (with reasons)

1. **rwh 0.6 field name** — PLAN §1 step 1 says `AppKitWindowHandle::ns_window`; rwh 0.6 names the field `ns_view` (winit's content `NSView`). The `NSWindow` is obtained from the view (`NSView::window()`) — same object, supported path. Documented in `macos.rs`.
2. **PLAN §1 steps 7–8 live in `suramak-ui`, not `suramak-glass`** — the alpha-mode pick and the transparent egui root are wgpu/egui concerns, not AppKit; `macos.rs` implements steps 1–6 exactly. The workorder's "steps 1–8" phrasing is satisfied across the two crates.
3. **`objc2-app-kit` features** — PLAN §10's list plus `NSGlassEffectView` (typed wrapper per PLAN-NOTES §2, behind the runtime `AnyClass` check) and `NSAppearance` (used by deviation 4). No dependency added.
4. **Window appearance pinned to DarkAqua (M1 placeholder decision)** — the static shell is designed light-on-glass; pinning dark makes it read identically on the user's Mac whatever their system appearance. Revisit when the real UI lands (M2+): support both appearances, or keep a deliberate dark design. This is the one place where "system-zenith" is knowingly not honoured yet.
5. **Comp deviations (documented per the direction contract)** — (a) the comp's iOS-style floating pill is *not* reproduced: record / play / export are drawn inside the window-chrome strip; (b) the comp's light content card is rendered as the dark glass world — opaque navy on Linux, translucent white washes over the real material on macOS; (c) the window title is drawn centred in the chrome (native title hidden). The comp is a generated render; native conventions and real materials win, and the measured layout (sidebar 23 %, serif title, scrubber strip, transcript column) is preserved.
6. **`suramak-ui` dependencies** — exactly PLAN §10 minus `rfd` (explicitly M2 per the workorder), including the target-gated `suramak-asr` with `capture` for macOS/Windows. `suramak-core`/`suramak-asr` are not yet *used* by the M1 shell (deps are per plan).
7. **`SURAMAK_WGPU_BACKENDS` env override** — added so the explicit backend chain is testable/debuggable (e.g. `=gl` forces the GL path); default chain is per-target as the workorder requires.
8. **Smoke semantics** — the N-second clock starts when the window exists (not at process start), and the file is written only after ≥1 presented frame; a no-frame run exits 1 *without* the file (never faked).
9. **`cargo fmt --all` does not reach cfg'd-out files** (`macos.rs`, `windows.rs` on Linux), so those two were additionally formatted/verified with `rustfmt --edition 2021 --check` directly (clean).
10. **Font-guard** — before handing system font bytes to epaint (which panics on unparseable fonts) the loader sniffs the sfnt magic; no new dependency, no font files.

### Extra verification (beyond the acceptance block)

- **Layout truth, independently checked**: `SURAMAK_SMOKE_SECS=6 ./scripts/xvfb-shot.sh` → `build/smoke.png`; an independent visual read of the screenshot confirms: dark navy window, chrome strip with centred title and record/play/export glyphs at the right, ≈23 % sidebar with 5 rows (row 2 "Wawancara — Klien" highlighted), serif title "Wawancara — Klien", waveform strip with ticks `0:00 … 24:10` and the playhead at the left, 3 transcript lines with mono timestamps; no clipping/overlap.
- **Backend chain exercised honestly**: Vulkan (lavapipe) was found first; the GL fallback path is implemented and reachable via `SURAMAK_WGPU_BACKENDS=gl` (each failure reason is printed).
- **macOS-only code paths** (font loading, `suramak_glass::apply`) are behind `cfg(target_os = "macos")` and are therefore not compiled by the Linux build. They were syntax-verified (`rustfmt --check`) **and type-checked** via a throwaway probe crate outside the repo (`~/.hermes/cache/scratch/m1-probe`) whose lib target points at the real `crates/suramak-ui/src/main.rs` with the real dependency set (`egui* 0.33.3`, `winit 0.30.13`, `suramak-glass`) for `aarch64-apple-darwin`:
