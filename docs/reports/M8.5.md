## What was implemented

### 1. `suramak-glass` — the float-glass surface

- **`FloatRect` + pure `float_rect(content_size, pixels_per_point) -> FloatRect`** (`src/lib.rs`): bottom-center of the content area, `FLOAT_INSET = 24` from the bottom edge, pill `184×52` at 1x, `FLOAT_SIDE_MARGIN = 16` of air when the window is too narrow; edges snapped to the device-pixel grid of `pixels_per_point` (degenerate scale values fall back to 1x). *One* definition, two consumers.
- **`GlassHandle`** — the new cross-platform handle `suramak-ui` talks to. `apply()` now returns `Result<GlassHandle, GlassError>` (it previously returned `()`):
  - `set_float_rect(Option<FloatRect>)` — `Some` shows/positions the float material (creating it lazily on macOS 26+), `None` hides it; a **clean no-op** on Linux, Windows and macOS < 26;
  - `float_glass_available() -> bool` — `true` only where a real material exists (macOS 26+, `NSGlassEffectView` present at runtime); the UI's cue to skip its painted pill.
- **macOS (`src/macos.rs`)**: the crash-fixed base arrangement is preserved — the base `NSGlassEffectView` stays the window's `contentView` and the render surface lives inside its `contentView` property. M8.5 inserts a **plain `NSView` container** as that property; winit's view and the float glass are its ordered subviews, the float ordered **directly below the render surface** (`addSubview:positioned:relativeTo:`, `NSWindowOrderingMode::Below`) — i.e. between the base material and the winit view. The float view is a second `NSGlassEffectView` (style `Regular`, corner radius = height/2), created on the first `Some(rect)`, hidden on `None`, frame set flipped-aware in the host's coordinate space. **It is never a `contentView`**, and it is never added as an arbitrary subview of a glass view (the header only guarantees z-order for the `contentView` property — see `docs/PLAN-NOTES.md`).
- **Linux (`src/stub.rs`) / Windows (`src/windows.rs`)**: no-op handles (`set_float_rect` does nothing, `float_glass_available` is `false`) — the UI paints its pill. The Windows DWM path stays exactly as before (**compile-checked only**, M4 policy: `apply` is not called there).
- `Cargo.toml`: two features added to the existing objc2-app-kit dependency — `NSGraphics` (`NSWindowOrderingMode`) and `objc2-core-foundation` (`CGFloat` for the corner radius). No new dependencies.

### 2. `suramak-ui` — the control itself

- **`app/views.rs`**: the titlebar red dot is **gone** (the titlebar keeps the M1 drag surface, title and the decorative play/export glyphs; `TOOLBAR_RESERVED` drops 158 → 96 for the two remaining glyphs). The new `float_control()` draws an `egui::Area` (`Order::Foreground`, non-movable, no fade-in) at exactly `float_rect(viewport, ppp)`:
  - **idle**: red dot + `Record` label (dimmed when unavailable — capture-less build or a running job);
  - **recording**: stop glyph + the live `mm:ss` clock (reusing `suramak_playback::format_mmss`), dimmed while the runtime finalises;
  - all input is egui's (`Sense::click` + pointing-hand cursor) — no hit-test juggling, no event plumbing;
  - the **fallback pill** (translucent fill, hairline, subtle shadow — palette `float_fill`) is painted only when `!state.float_glass`, i.e. nowhere the real material stands behind the pixels (M9 material ladder: an honest frosted pill, never a Liquid Glass imitation).
- **`app/mod.rs`**: `AppState::toggle_record(now, date)` — THE record entry point: idle → `StartCapture` (the effect the old dot emitted), recording → `StopCapture` (the record view's Stop effect, final path → transcript), finalising → no-op, unavailable → the old dot's status lines. New `float_glass: bool` field (seeded by the shell; a field so the state is headless-testable). `busy()` already covered `Recording` — now pinned by a dedicated test.
- **`shell.rs`**: owns `Option<GlassHandle>`; seeds `app.float_glass` from `float_glass_available()`; applies the rect on creation, in `resize()`, and — keyed on (physical size, scale factor) — after any geometry change in `redraw_or_log()` (catches ppp moves without a `Resized` event, and re-applies with settled AppKit bounds after a resize). No-op without a handle.
- **`theme.rs`**: `float_fill` (macOS: a translucent white wash like the other M1 surfaces; elsewhere: a lifted navy `#1e2a54` at 85%).
- **`app/record.rs`**: the stale "Press the red dot in the title bar" copy now points at the floating control.

## Deviations / choices (with reasons)

1. **The float glass is ordered into a new plain container** (the base glass's `contentView` becomes a plain `NSView`; winit's view and the float glass are its ordered subviews). This is the only way to make the float glass an *ordered* subview "between the base material and the winit view" without (a) making it an arbitrary subview of a glass view (the header's z-order warning; the crash class of `ed1fee1`) or (b) making the winit view a plain sibling above the glass (exactly the arrangement that aborted with `AppKit/NSGlassEffectView.swift:736: Fatal error`, macOS 27). The window's `contentView` stays the base material — never a glass view added by M8.5. Recorded in `docs/PLAN-NOTES.md`.
2. **`GlassHandle` is new** — the crate previously had no handle (`apply` returned `()`); the workorder's "existing cross-platform handle" did not exist yet, so it was introduced and `apply`'s return type changed. Only caller updated: `shell.rs`.
3. **The rect type is `suramak_glass::FloatRect`, not `Rect`** — the crate must not depend on egui; the UI converts to `egui::Rect` in one line.
4. **`content_size` is in logical points** and `pixels_per_point` is used to snap the rect to the device-pixel grid (crisp edges at any scale). The signature follows the workorder; the units are documented on the function.
5. **The macOS float view is created on the first `set_float_rect(Some(..))`** (lazy), hidden on `None`, re-applied by `shell.rs` on creation, on every `resize()`, and after any (size, scale-factor) change — this satisfies "applied on create and on resize" and also fixes ppp-only moves.
6. **The titlebar's play/export glyphs stay** — they are M1 chrome decorations (never interactive), not record affordances; the M9 chrome remake owns them. Only `TOOLBAR_RESERVED` was adjusted (158 → 96).
7. **Windows' DWM path stays dormant** (`apply` is not called there — the M4 "compile-checked only, no runtime claims" policy), so the float control is a painted pill on Windows; `suramak-glass` cross-checks for `x86_64-pc-windows-msvc` still pass.
8. **The clock reuses `suramak_playback::format_mmss`** (the app's existing `mm:ss` formatter) — no new formatting code, no new dependency.
9. **`objc2-app-kit` gained the `NSGraphics` + `objc2-core-foundation` features** (same crate, needed for `NSWindowOrderingMode` and `CGFloat`/`setCornerRadius`). No new crates; `Cargo.lock` unchanged.
10. **The fallback pill paints no material where the real one exists** (`float_glass == true` → glyph/label/time only): the glass is behind the pixels, per the workorder's "egui draws the crisp glyph/label/time" and the M9 "no fake Liquid Glass off Apple platforms" ladder.

## Blockers (honest status)

1. **The macOS glass material itself is not runtime-verifiable from this VPS.** The float `NSGlassEffectView`, its z-order between the material and the render surface, and the modal-panel safety of the new container arrangement are verified only by the `aarch64-apple-darwin` compile check, the design review against `NSGlassEffectView.h`'s documented contract, and the recorded crash history (PLAN-NOTES). The owner's smoke (item 15) is the first real test.
2. **The enabled record visuals (stop glyph + live ticking clock while a real session runs) are covered by state tests only** — the Linux build has no capture compiled in, so the E2E shows the disabled state and the click's status answer. The clock update path itself (`tick` → `elapsed` → `format_mmss`) is unit-tested.
3. **macOS < 26 (the painted-pill-on-real-material path) is unverifiable here** — no `NSGlassEffectView` class exists on those machines by definition; `set_float_rect` no-ops and the same painted pill from the Linux screenshots renders over the `NSVisualEffectView` material.
