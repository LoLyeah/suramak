## Routing (pure function — `suramak-asr::engine::resolve_engine`)

- `fast == false` (the default) → **exactly today's routing** for every language.
- `fast == true` **and** `setting == Auto` **and** a **forced covered** language
  (the 25-language list) **and** `parakeet_compiled && parakeet_installed` →
  `EngineId::Parakeet`.
- **Indonesian (`id`, `ID`, `id-ID`) → never Parakeet** — a hard guard in
  `models::parakeet_covers` plus the invariant asserted over the whole
  availability matrix in the tests (and e2e on the real install).
- Auto-detect (`None`) → Whisper (the language is unknown at plan time).
- Uncovered languages → Whisper. An explicit `coreml`/`metal`/`cpu` request → that
  whisper backend (the toggle never overrides an explicit request).
- A covered language with the fast engine unavailable → Whisper with a warning
  (`fast engine requested but the Parakeet model is not installed (run
  `suramak-cli models download parakeet`) — using cpu`) — never a hard failure.

## Deviations from the WORKORDER (with reasons)

1. **Per-file pinned downloads instead of `.tar.bz2` extraction.** Upstream ships
   the same artifacts both as `sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8.tar.bz2`
   (GitHub releases) and as individual files (the k2-fsa HF mirror). The
   workorder's flow was “download → sha256 verify → extract → layout check”; the
   implementation downloads the four files individually (resume + sha256 per file
   → layout check) because: (a) per-file hashes are stronger than one archive
   hash; (b) it needs no new bzip2/tar extraction path in `suramak-core`, which is
   deliberately pure-Rust (`zip` with the pure-Rust zlib backend — adding
   C-compiled bzip2 would break that rule); (c) the resulting directory layout is
   identical to the archive's. The pin script prints the same per-file values.
2. **`cargo check -p suramak-ui --target aarch64-apple-darwin` cannot pass from
   Linux** (pre-existing C-dependency limitation; M1.5 deviation 10). Mitigated
   with the darwin feature-tree check + the `build/probe-darwin` compile check
   (above); the real darwin build runs on the macOS CI job / the owner's Mac.
   `build/probe-darwin` needs
   `BINDGEN_EXTRA_CLANG_ARGS_aarch64-apple-darwin=--target=x86_64-unknown-linux-gnu`
   so bindgen (which follows cargo's `TARGET`) generates the C bindings with the
   host clang config; the Rust code is still type-checked for darwin. Apple-only
   declarations in `c-api.h` are irrelevant to our calls (provider is a string).
3. **`EngineAvailability::current` derives the Parakeet install from
   `model_path.parent()`** (the models dir next to the whisper model file). A
   custom whisper path outside the models dir therefore never selects the fast
   engine — honest and documented.
4. **The fast engine applies only while `settings.asr.engine == Auto`.** An
   explicit `--engine coreml|metal|cpu` means “run whisper on this backend” and
   wins over the toggle (the toggle is an auto-routing policy, not a whisper
   backend). Documented in `engine.rs` + ENGINES.md; tested.
5. **Auto-detect (`--lang auto`) stays whisper.** With an unknown language an
   Indonesian clip could otherwise reach Parakeet — the honest default is Whisper.
   Documented; tested.
6. **`--fast` CLI flag added** (beyond the settings toggle) so the e2e and the
   acceptance runs can exercise the engine without editing `settings.toml`;
   flags-beat-settings matches the existing `--engine` pattern.
7. **The UI Models screen does not list the Parakeet model.** The workorder's
   “model-manager support” is core + CLI + doctor (the same manifest mechanism);
   the Do-NOT clause (“no UI redesign beyond the one settings control”) kept the
   UI to the toggle + the engine line. Install/remove via `suramak-cli models …`
   (USER_SMOKE 28).
8. **`worker.rs` dispatches on the plan** (`EngineId::Parakeet` → the parakeet
   pipeline, else the whisper flow). The engine *selection* stays the pure
   function; the worker had to choose which pipeline to run because the whisper
   path requires a `WhisperContext` that the fast engine must never load.
9. **`download_files` verifies sizes as well as sha256** (cheap pre-filter with a
   clearer error for a truncated file). The pins carry both, so the size is used,
   not decorative.
10. **The Parakeet load is ~6 s on this VPS** (652 MB of ONNX); the recognizer is
    cached per worker (`ParakeetCache`), so only the first job pays it. On the
    Mac this will be dominated by the Core ML/ONNX load — owner-verify.
11. **`LD_LIBRARY_PATH` is needed on Linux** for the sherpa-onnx shared libraries
    the sherpa-rs build script copies next to the binary (`target/<profile>` and
    `target/<profile>/deps`). Documented in ENGINES.md; the macOS app-bundle
    packaging of those dylibs is a follow-up (owner/M10B).
