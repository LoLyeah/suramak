# M20A — the type + motion foundation (Android-first)

Executed per `docs/WORKORDER-M20A.md` (slice 1 of 5 of
`docs/reports/M20-ui-refresh-plan.md`). This slice changes *what the phone
draws with*, not *what it draws*: five OFL static faces are bundled and
registered on every platform, the plan's type scale becomes callable tokens,
and the screen-facing motion vocabulary grows the five helpers the plan's
table names — each with a repaint discipline that is proved by test.

**Run status.** Implemented and verified on this VPS with real commands: the
full workspace suite (**1,202 passed / 0 failed**, baseline 1,186 + 16 new),
`clippy --workspace --all-targets -D warnings`, `fmt --check`, the Android
cross-check (`cargo ndk -t arm64-v8a check` + `clippy` on `suramak-android`
and `suramak-android-spike` — the host suite cannot see `cfg(android)` code),
and `scripts/fonts/build_fonts.py --check` reproducing all five files byte for
byte. The phone and desktop goldens were re-blessed by their own suites. **The
emulator smoke did not run here** (no `/dev/kvm`, no emulator package on this
host); the Android proof in this report is the compile/clippy cross-check, not
a device run.

---

## 1. The defect

`theme.rs::load_system_fonts` was `#[cfg(target_os = "macos")]`. On Android —
and on the Linux goldens — nothing loaded, so every string rendered in egui's
2019 fallbacks (Ubuntu-Light / Hack). epaint 0.33 rasterises with `ab_glyph`,
which cannot interpolate a variable font's `wght` axis or toggle OpenType
features, so "just ship the variable TTF" was never an option: the faces have
to be static instances and they have to be subsetted.

## 2. The bundled faces

`assets/fonts/` now holds five static, subsetted faces plus `OFL.txt` (the
three upstream copyright notices and the full OFL 1.1 text) and
`PROVENANCE.md` (generated by the build script from the same table, so the
note cannot disagree with the bytes). They are embedded with
`include_bytes!` — no runtime asset lookup, nothing extra to copy into the APK.

| file | face | weight | role | bytes | glyphs |
|---|---|---|---|---|---|
| `Inter-Regular.ttf` | Inter Regular | 400 | `Proportional` — body, row values, captions | 43,532 | 607 |
| `Inter-Medium.ttf` | Inter Medium | 500 | `SansMedium` — row titles, numerals | 43,536 | 607 |
| `Inter-SemiBold.ttf` | Inter SemiBold | 600 | `SansSemiBold` — screen titles, section labels | 43,768 | 607 |
| `Newsreader-Regular.ttf` | Newsreader Regular | 400 | `serif_family()` — editorial display | 32,148 | 399 |
| `GeistMono-Regular.ttf` | Geist Mono Regular | 400 | `Monospace` — diagnostics, hashes, paths | 21,864 | 350 |

Total **184,848 bytes (181 KB)**; the largest face is 43,768 B against the
workorder's 120 KB ceiling.

The full 64-hex hashes are in `assets/fonts/PROVENANCE.md`; the table above is
the same data abbreviated for reading. Every upstream hash is **pinned as a
constant in `scripts/fonts/build_fonts.py`** — a changed upstream fails the
build instead of silently changing the shipped faces.

Subset: `U+0020-024F` + `U+2000-206F` + `U+20AC` + `U+2122` +
`U+2190-2193`. Hinting (unused by `ab_glyph_rasterizer`), GPOS/GSUB (unused by
`ab_glyph`), and the variable tables are dropped; no other flags. All three
families' upstream files carry no legacy `kern` table, so kerning was not
available to epaint before this slice and is not lost by it.

### 2.2 Reproducibility

`scripts/fonts/build_fonts.py` is committed and is the only producer:

```sh
/usr/bin/python3 scripts/fonts/build_fonts.py            # rebuild assets/fonts/
/usr/bin/python3 scripts/fonts/build_fonts.py --check     # rebuild in a temp dir, compare bytes
```

It verifies each produced file loads with `fontTools.ttLib.TTFont`, is static
(`fvar` gone), carries the required characters (all ASCII, Latin-1 letters,
`– — ‘ ’ “ ” … € ™`), has the expected family name in its name table, and
prints each sha256. `--check` currently prints *"ok: the 5 committed faces are
reproducible byte for byte"*. Reproducibility required `TTFont(...,
recalcTimestamp=False)`: fontTools otherwise stamps `head.modified` with the
current time on every save.

**What the plan asked for but this slice did not do:** `cv05` (disambiguated
`l`/`1`) and a baked `tnum` are OpenType feature substitutions — applying
them offline means rewriting glyph outlines or remapping the cmap, not
toggling a flag. The workorder already softened this ("fixed-width cells
helper until tnum proves out"), so numerals use
`type_scale::numeral_cell()` / `numeral_run()`, built on Inter Medium's own
tabular advance **0.6479 em** (read from the `tnum` alternates in the
instance, not guessed). A `tnum` bake is a candidate for a later slice; it
would replace the helper, not the face.

## 3. Registration (`theme.rs`, table in `deck/fonts.rs`)

`register_fonts(&mut FontDefinitions)` applies one platform table and returns
a `Registered { sans, medium, semibold, serif, mono }` record:

| platform | `Proportional` | `SansMedium` | `SansSemiBold` | `serif_family()` | `Monospace` |
|---|---|---|---|---|---|
| macOS | SF Pro (`SFNS.ttf`) | SF Pro (no static 500) | SF Pro (no static 600) | New York | SF Mono |
| Android / Windows / Linux | Inter Regular | Inter Medium | Inter SemiBold | Newsreader | Geist Mono |

* The macOS paths and ids are unchanged from M9a and are pinned by
  `fonts::MACOS_SYSTEM` (a test asserts the three paths on every host).
* The macOS system files are still loaded at runtime and a missing file still
  degrades silently to egui's stack (PLAN §1).
* The named weight families exist on **both** platforms, so a screen can call
  `theme::sans_medium()` without a `cfg`. On macOS they resolve to SF Pro's
  default instance: `SFNS.ttf` is a variable font and epaint cannot instance
  it, so there is no static Medium/SemiBold to load. **Consequence, stated
  plainly: the 500/600 steps in the type scale render as Regular on macOS and
  as true Medium/SemiBold on the other platforms.** macOS rendering is
  otherwise exactly M9a's, as the workorder requires.
* The serif and weight families fall back through the *post-prepend*
  proportional stack (Inter before Ubuntu-Light), so a glyph the display face
  lacks cannot turn into an egui fallback glyph mid-title.
* Off macOS the five faces are `FontData::from_static(include_bytes!(…))`;
  on macOS the `include_bytes!` constants are `#[cfg]`-gated out, so a macOS
  binary does not carry ~181 KB of unused faces.

## 4. The type scale (`deck/type_scale.rs`)

Every value from the plan's table, as a callable token. Sizes are egui points;
tracking is egui's `extra_letter_spacing`; line height is provided for callers
that measure rows themselves.

| role | helper | face | size | tracking | line |
|---|---|---|---|---|---|
| Screen title | `title()` | Inter SemiBold 600 | 22 | −0.4 | 28 |
| Editorial display | `editorial_display()` | Newsreader 400 | 21 | −0.2 | 27 |
| Section label | `section_label()` | Inter SemiBold 600 | 11 | +0.8 | 16 |
| Row title | `row_title()` | Inter Medium 500 | 15 | −0.1 | 20 |
| Row value | `row_value()` | Inter Regular 400 | 14 | 0 | 20 |
| Body / transcript | `body()` | Inter Regular 400 | 15.5 | 0 | 24 |
| Caption / meta | `caption()` | Inter Regular 400 | 12.5 | +0.1 | 17 |
| Numerals | `numerals()` | Inter Medium 500 | 12.5 | 0 | 16 |
| Mono (earned) | `mono()` | Geist Mono 400 | 11.5 | 0 | 16 |

`TypeToken` exposes `rich(text)` for widgets and `format(color)` (a
`TextFormat`) for the painted rows, so both paths carry the same face,
tracking and line height.

**Not wired into the screens in this slice** — the workorder forbids screen
restyling here. The goldens moved because the faces changed, not because a
size did.

## 5. The motion vocabulary (`deck/motion.rs`)

The M9a `Motion` helpers animate an egui `Id` through the context (desktop
widgets). The phone's transitions are caller-owned state machines, so M20A
adds a pure family that takes `now` and returns values; every helper ends
exactly at its endpoint and reports `running`.

| interaction | helper | token | what moves | Reduce Motion |
|---|---|---|---|---|
| Screen push / pop | `ScreenMotion::push/pop` | SLOW 240 ms, cubic-out | incoming ±24 pt → 0 X + alpha 0→1; outgoing ∓8 pt + alpha 1→0 | FAST 120 ms crossfade, no travel |
| Sheet present / dismiss | `SheetMotion::present/dismiss` | SLOW 240 ms | `slide` 1→0 of the sheet height + scrim 0→1 + alpha | FAST crossfade, no slide |
| Row / button press | `PressMotion` | FAST 120 ms in; 240 ms spring out | scale 1.0 → 0.97 + `control_active` fill 0→1 | fill swap only, no scale |
| Success / completion | `SuccessBadge` | BASE 180 ms scale; SLOW flash | scale 0.88 → 1.0 + `ok` flash 0.22 → 0 | instant checkmark (scale 1, no flash) |
| Scroll rubber-band | `RubberBand` | BASE 180 ms release | resisted, signed, ≤4 pt offset past a bound; returns to 0 on release | hard clamp (offset 0) |

**Repaint discipline.** `AnimationClock` aggregates each helper's `running`
into one flag; `clock.request(ctx)` calls `request_repaint()` **only while
that flag is set**, and nothing else in the module requests a frame. There is
deliberately no `request_repaint_after`: a timer is how an animation becomes an
idle loop. A unit test drives all five helpers on a real `egui::Context`,
proves a mid-flight frame asks for a repaint, and proves **three consecutive
steady frames at t ≥ 1 ask for none**.

Helper-level tests also pin: push/pop travel and exact endpoint; sheet slide,
scrim and alpha; press's FAST-in/spring-out with the flip frame holding its
value; the success badge's scale landing on BASE while the flash outlives it
on SLOW; the rubber-band's sign, monotonicity and 4 pt bound; and each
Reduce-Motion substitution.

### 7.1 One desktop wrap defect the font exposed

The full suite caught `the_captions_wrap_at_the_minimum_pane_instead_of_clipping`
(`desktop/app/settings.rs`): the Appearance caption's right edge reached
897 pt in a 900 pt window whose pane ends at 874. Two separate causes, both
fixed in this slice because an intentional font change must not leave a
red suite behind:

* `row_caption` measured its wrap width against `ui.clip_rect()`, which inside
  the settings scroll area can be the **window** edge while the pane's padded
  edge is 26 pt inside it. Inter is narrower than Ubuntu-Light, so for the
  first time a row filled the whole clip and the pre-existing overshoot became
  visible. The width is now clamped to `clip.right() − PANE_PAD_X` (the same
  `PANE_PAD_X` every other settings edge uses).
* At the corrected 491 pt column the Linux caption no longer fitted in two
  lines — it wrapped to three with `Save.` alone on the last. The Linux
  sentence was tightened (same facts, same phrases the copy tests pin:
  "Linux", "when the desktop reports one", "falls back to", "forces this
  app's appearance", "Applied when you press Save."), exactly the M14e
  Windows precedent. It now wraps 484 + 305 pt on two lines.

No other screen layout moved: the form's own overflow (a control in the
Transcription section widens the scroll content to 950 pt inside a 641 pt
viewport) is **pre-existing and out of scope** for a font slice — it is
recorded here as a desktop finding for a later cleanup, not hidden.

## 8. The honest boundary

* **Phone screens still use the old layout.** This slice adds tokens and
  helpers; `library.rs`, `settings.rs`, `editor.rs`, the sheets and the dock
  are untouched. The plan's layout work (frosted material, floating dock,
  grouped cards, de-jargoning) is slices M20B–E.
* **The type scale is unused by screens** for the same reason. Its first
  consumers arrive in M20C/D/E.
* **No screen uses the new motion helpers yet**; the compact profile still
  drives its push/pop and sheet through `deck/nav.rs` and
  `deck/compact/motion.rs`. The new helpers are additive and tested, not
  swapped in — swapping them is a screen slice.
* **macOS has no true 500/600 step** (see §3): SF Pro is variable and epaint
  cannot instance it. The named families exist and resolve to SF Pro.
* **`cv05` / baked `tnum` are not shipped**; numerals use fixed cells (§2.2).
* **The emulator smoke was not run on this host.** The Android compile and
  clippy cross-check passed; the smoke must stay green in CI, and nothing in
  this slice touches the shell, the JNI bridge or the surface.
* **Newsreader and Geist Mono carry a narrower repertoire than Inter** (no
  arrows, partial Latin Extended-B — those ranges are not in the upstream
  files). They are earned display/mono faces; missing characters fall through
  to the proportional stack, i.e. Inter.
