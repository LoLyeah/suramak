0.8.4 is the build where the phone stops lying to you. Every defect in this release came from your screenshots: a job that ran with progress visible only in the notification shade, a Library that stayed empty until you opened Settings and came back, a timecode painted through a button, `Line length 165` in the middle of a transcript, and word chips drawn across the rows below them.

The common cause of the first two was not the job queue — that was working — but the surface: egui only repaints when there is input, so with the phone idle the Library never re-read itself, and the job strip the UI already had was never fed by the Android shell. Both are wired now, so a finished transcript appears on its own and a running one shows `Preparing the file · 40 %` → `Preparing the audio` → `Transcribing · 42 %` above the list.

A failure now stays where you can see it: a red strip on the Library with the job's name, the host's own sentence and one **Dismiss** button. Diagnostics gained a **Last job** card with the same information, and the Device card finally shows the session limit the app enforces — computed from this phone's memory, with the model it was computed for.

The build side had its own afternoon: the CI image moved to CMake 4.5, which refuses the NDK's Ninja version probe and left libopus unable to configure, and the sherpa-onnx build script panics without an errno when its destination directory is missing. Both are fixed at the root — CMake is pinned for the Android job, and the macOS/Windows jobs prepare the destination — rather than by retrying until it turns green.
