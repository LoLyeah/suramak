0.8.2 makes a stuck job say so instead of sitting at 0 %. If you install this and an import fails, it will tell you why — that is the main change.

Two bugs were behind the 0 % hang you hit. A journal row whose copy never finished — an import interrupted by a crash or by leaving the app — came back as a *Pause* the app refuses to resume, and while it sat in `copying` the status line reported `running: true, percent: 0` for a job that had no copier at all. The service waited on it forever. That row is now a named failure with a message, and its half-written file is deleted. The service also fails a copy that shows no byte progress for two minutes, or any phase frozen for ten, quoting the phase and percentage.

The Library no longer needs a relaunch to show a finished job: it compares what is stored with what it is showing once a second and reloads when they differ.

### What is proven, and where

- **Linux, real `small` model, real audio:** a fresh import goes `queued → transcribing → done` in ~44 s, and a kill-then-Resume also completes. The queue, journal and resume logic are sound.
- **The Android emulator, real model, real job:** the job is observed copying (`percent=100`) and then transcribing (`percent=0`) — the service path runs end to end. Getting the emulator to that point exposed three harness faults, not product faults: `adb push` cannot write into the app's files dir on Android 13+, the voice-note sheet needs an explicit accept before anything is queued, and a cached-process reclaim was being scored as a crash.

### Still open

The session limit is computed from the device's memory but has no row on the Device card yet — the number is real, the label is missing. That is the next change.
